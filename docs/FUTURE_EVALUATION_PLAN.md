# Protocol for Evaluating Future Real-World Flip-It Puzzles

This evaluation plan establishes the rigorous scientific methodology for testing Flipit Finder against real-world, out-of-lexicon puzzles collected from published games or external player submissions.

---

## 1. Dataset & Engine Freeze Milestone

Before ingesting any real-world puzzles:
1. **Repository Freeze**:
   - The runtime lexical database (`data/wordnet_relationships.json`), curated relationship dictionary (`data/relationships.json`), and phrase databases (`data/moby_phrases.json`, `data/phrases.json`) must be cryptographic-hash frozen.
   - The solver engine, ranker heuristic formula, and priority constants must remain unchanged.
2. **Strict Prohibition on Pre-Seeding**:
   - The evaluation puzzle clues and target answers must **never** be used to update, patch, or seed the relationship engine or phrase database prior to running the evaluation.
   - Any manual seeding of test clues constitutes benchmark leakage and renders accuracy metrics invalid.

---

## 2. Real-World Corpus Ingestion Protocol

1. **Source Collection**:
   - Collect $N \ge 50$ real-world Flip-It puzzles from published daily word games, newspapers, or blind submissions.
   - Record clue 1, clue 2, official target phrase, and any given letter/length constraints.
2. **Blind Input Format**:
   - Store puzzles in `data/realworld_frozen_eval.json`.
   - Each entry contains: `id`, `clue1`, `clue2`, `expectedWord1`, `expectedWord2`, `expectedPhrase`, `constraints`.

---

## 3. Evaluation Execution & Metrics

The frozen solver is executed against the entire test set in zero-shot mode:
- **Top-1 Exact Match Accuracy**: The percentage of puzzles where the solver's top-ranked candidate (`bestMatch`) matches the official target phrase.
- **Top-5 Recall**: The percentage of puzzles where the target phrase appears within the top 5 ranked candidates.
- **Zero-Candidate Rate**: The percentage of puzzles where no recognized collocation candidate could be formed.

---

## 4. Formal Error Taxonomy & Attribution

For every puzzle where the top match does not equal the expected phrase, the error must be strictly categorized into one of three independent failure modes:

1. **Lexical Recall Failure (Missing Relationship)**:
   - Clue 1 or Clue 2 does not yield the required target word in `solver.relationshipProvider.getTransformations()`.
   - *Cause*: The semantic relation is absent from both WordNet 3.0 core seed data and the curated association lexicon.
2. **Phrase Recall Failure (Missing Collocation)**:
   - Both target words are successfully generated by the relationship engine, but the two-word pairing is absent from both the Moby compound lexicon and the phrase database (`solver.phraseProvider.matchPhrase()` returns `null`).
   - *Cause*: Collocation repository coverage gap.
3. **Ranking Failure (Displaced Best Match)**:
   - The expected target phrase is successfully generated as a candidate, but another competing candidate achieved a higher `matchScore`.
   - *Cause*: Heuristic weight imbalance between relation strength and phrase frequency.
4. **Constraint Incompatibility**:
   - The puzzle constraints (e.g. length, first letter) filter out the expected word due to spelling variants or rule conflicts.

---

## 5. Reporting & Integrity Standards

- Published evaluation reports must report:
  - Total real-world puzzles evaluated.
  - Frozen commit SHA and timestamp.
  - Number of Lexical Recall Failures, Phrase Recall Failures, and Ranking Failures.
  - Unassisted Zero-Shot Accuracy.
- Puzzles evaluated in this manner may subsequently be analyzed for error patterns, but must not be retroactively claimed as "unseen generalization" if added to future test suites.
